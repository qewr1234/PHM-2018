# CMP 연마량 예측 (PHM 2016 Data Challenge)

웨이퍼 연마 장비(CMP, Chemical Mechanical Planarization)의 센서 로그와 소모품 사용량으로 웨이퍼마다 평균 연마량(Material Removal Rate, MRR)을 예측하고, 드레서·패드 마모가 연마 성능에 주는 영향을 물리 모델로 해석한 프로젝트입니다.

- 데이터: [PHM Society 2016 Data Challenge](https://phmsociety.org/conference/annual-conference-of-the-phm-society/annual-conference-of-the-prognostics-and-health-management-society-2016/phm-data-challenge-4/) (학습 웨이퍼·스테이지 1,981건, 테스트 424건, 검증 424건, 정답 공개)
- 결과 대시보드: `cmp2016/dashboard/index.html`

### 이전 버전과 비교

| 파이프라인 | 특징 수 | in-sample CV | **nested CV** | 테스트 | 검증 |
|---|---|---|---|---|---|
| 이전: LightGBM 2종 + ExtraTrees + 릿지, 전역 NNLS | 112 | 7.596 | 8.109 | 6.969 | 6.850 |
| 이전 멤버 + 결합 방식만 고침 (클리핑 + 레짐별 NNLS) | 112 | 7.490 | 7.543 | 6.856 | 6.789 |
| **최종: 시퀀스 모양·이웃 확장 특징 + LightGBM·융합 신경망·GP** | 580 | 6.568 (이전 정의 6.693) | **6.608** | **6.445** | **6.099** |

- **nested CV 가 정직한 수치입니다.** in-sample CV 는 학습 데이터 전체의 교차검증 예측(OOF)으로 가중치를 맞춘 뒤 같은 행에 채점한 값이라 낙관적입니다. 이전 버전의 전역 NNLS 는 in-sample 7.596 이었지만 폴드마다 가중치를 다시 맞추면(nested) 8.109 였습니다: 릿지가 4B 한 웨이퍼에 -84.7 을 예측해 폴드마다 가중치가 뒤집혔기 때문입니다. nested CV 는 폴드마다 학습 폴드 OOF 로만 클리핑 범위와 가중치를 정해 held-out 폴드를 채점합니다.
- 최종 in-sample 6.568 은 실제로 쓰는 결합(레짐별 클리핑 NNLS)의 값이고, 괄호 안 6.693 은 이전 버전과 같은 정의(전역 NNLS)로 계산한 비교용 값입니다.
- 폴드 시드 2 로 다시 확인: nested 6.624, 테스트 6.368, 검증 6.073 (시드 0 과 같은 수준). 시드 0·1 은 탐색에서 소진됐으므로 최종 확인은 시드 2 로 했습니다.
- 연마 조건별 (시드 0): nested CV 1A 6.031 / 4A 5.719 / 4B 7.736, 테스트 1A 9.188 / 4A 5.558 / 4B 6.156, 검증 1A 6.781 / 4A 5.456 / 4B 6.525. 챔버 그룹 1(1A) 은 어떤 특징도 도움이 되지 않던 조건인데 CV 에서는 GP 멤버(가중치 0.83) 덕에 나아졌지만 테스트에서는 따라오지 않았습니다(이전 버전 9.440 → 9.188; 검증은 6.956 → 6.781).

## 설비 관점에서 읽은 것

- **드레서가 연마 성능의 핵심 레버입니다.** 챔버 4에서 드레서가 닳을수록 연마량이 약 11~14% 줄었습니다. 드레서가 패드를 거칠게 되살리지 못해 패드가 매끈해지면(글레이징) Preston 계수가 떨어지는 것과 맞습니다.
- **공정 설정보다 소모품 상태가 차이를 만듭니다.** P·V는 웨이퍼마다 6~9% 달랐지만 연마량은 이를 따라가지 않았습니다(아래 기계공학 관점 분석).
- **소모품 카운터만으로는 부족합니다.** 물리 모델은 평균 예측 대비 테스트 MSE를 51.6 → 44.1로 줄이는 데 그쳤고, 가까운 시각에 처리된 웨이퍼의 측정 결과를 반영하는 것이 훨씬 효과적이었습니다(run-to-run 제어와 같은 발상).
- **같은 챔버 그룹의 A·B 스테이지는 함께 움직입니다.** 다른 스테이지의 최근 결과를 넣자 교차검증 MSE가 8.11 → 7.78로 줄었습니다.
- **레시피가 같아도 "실제로 연마된 시간"은 웨이퍼마다 다릅니다.** 가장 강한 단서는 여전히 가까운 시각 웨이퍼의 측정값(이웃 특징)이지만, 원시 센서 시퀀스의 모양 특징이 레짐별 LightGBM gain 의 9~16% 를 차지하고 그중 첫 단계에서 주 에어백 압력이 정체 수준의 90% 이상인 시간(`s0_mo_hi_sec`, 4B 에서 gain 5.7%)과 가압 구간 길이(`s0_active_span_sec`)가 앞섰습니다. 설정값(P·V)이 아니라 설정에 머문 시간과 전이 구간이 연마량 차이의 일부를 설명합니다.
- **"마지막으로 측정된 웨이퍼 이후 무엇이 달라졌나"가 정보입니다.** 직전 웨이퍼의 측정 결과만이 아니라 그 웨이퍼와 이 웨이퍼의 공정 상태 차이(가공 시간, P·V 적분, 슬러리, 에어백 압력, 드레서·패드 사용량), 최근 편차의 지수가중 평균, 같은 웨이퍼 다른 스테이지의 편차를 함께 주자(NB_ 확장 특징 50개) nested 교차검증 MSE가 7.02에서 6.80으로 줄었습니다.

## 기계공학 관점 분석 (`mech_analysis.py`)

예측 모델과 별개로, 정답이 공개된 웨이퍼 전체(2,825건)로 장비 물리 가설을 검증했습니다.

**1. 드레서 교체 전후 비교 (자연 실험).** 약 65일 동안 드레서가 3번 교체됐습니다. 교체 직전·직후 20장의 평균 연마량(Welch t-검정):

| 연마 조건 | 교체 1 (6일째) | 교체 2 (27일째) | 교체 3 (46일째) |
|---|---|---|---|
| 챔버4·A | +17.1 | +5.2 | +3.0 (p=0.008) |
| 챔버4·B | +16.1 | +15.5 | +6.2 |
| 챔버1·A | +4.1 | -0.6 (p=0.43) | -1.0 (p=0.33) |

표시가 없는 값은 모두 p<0.001입니다. 다만 챔버4의 세 번 모두 연마 테이블 사용량 카운터도 같은 날 초기화돼(동시 정비), 교체 직후 상승을 드레서 하나의 효과로 단정할 수 없습니다.

**2. 드레서 수명 안 기울기.** 수명별 절편을 둔 회귀로, 같은 드레서를 쓰는 동안 사용량 100당 연마량이 챔버4·A -0.80 ± 0.07, 챔버4·B -0.85 ± 0.09 변했습니다(챔버1·A +0.12 ± 0.08, 효과 없음). 수명 전체(사용량 약 770)로 보면 약 8% 감소입니다.

**3. 마모 곡선 모양.** 수명 초반에 오르고(길들이기), 중간은 완만하고, 사용량 700 이후 더 떨어지는 경향이 보여 전형적인 마모 곡선(초기·정상·급격 마모)과 비슷합니다. 표본이 적어 경향 수준입니다.

**4. Preston 식 점검.** 실제 연마 구간의 P·V는 웨이퍼마다 6~9% 달랐지만(변동계수), 연마량과의 순위 상관은 챔버4·A -0.15, 챔버4·B 0.02로 P·V를 따라가지 않았습니다. 웨이퍼 간 연마량 차이는 설정값(P·V)보다 연마 효율 Kp의 변화에서 온다고 봅니다.

**확인하지 못한 것.** P·V 범위가 좁아 Stribeck 곡선(윤활 상태)은 확인할 수 없고, 압력·속도를 바꾸는 실험(DOE)이 필요합니다. 장비 치수가 공개되지 않아 실제 상대 속도(기구학)도 계산하지 못했습니다.

```bash
python cmp2016/mech_analysis.py   # 약 30초, cmp2016/mech_results.json
```

## 방법

### 1. 특징 (`cmp_data.py`, 580개)

- **기본 (112)**: 웨이퍼·스테이지마다 챔버 3곳의 단계별 압력·회전·슬러리 요약, 소모품 6종 사용량, 압력 × 회전 속도의 시간 적분(Preston 항), 가공 시간. 여기에 이웃·순서 특징: 시간·소모품 상태가 가까운 학습 웨이퍼의 연마량, 국소 추세, 처리 순서상 앞뒤 웨이퍼(같은 챔버 그룹의 다른 스테이지 포함)의 연마량 편차.
- **시퀀스 모양 `TS_*` (418, 정답 미사용)**: 원시 1 Hz 센서 행을 챔버 단계(0·1·2)와 채널(압력 6, 슬러리 3, 회전 3)마다 요약합니다. 램프업/램프다운 시간, 정체 수준 ±5% 밴드 진입 시각, 정체 수준의 90% 이상 유지 시간, 정체 구간 기울기와 전후반 차, 수준 변화 횟수(런렝스), 채널 간 시작·종료 지연(슬러리가 압력보다 먼저 켜지는가), 단계 앞뒤 비활성 시간, 드레싱 워터 토글 수. 레시피가 압력·회전을 거의 고정하므로 "얼마나 오래, 어떤 전이를 거쳐 연마됐는가"가 웨이퍼 간 차이를 설명합니다. 1,109 개 후보를 정답 없이 가지치기(결측 95% 이상·상수·기존 표나 앞선 컬럼과 |상관| > 0.98 제거)한 뒤 timing·ramp·drift·levels·lag 가족만 남겼습니다(수준·분위수 가족은 단계별 평균과 겹쳐 제외). 한 번 계산해 `data/cmp2016/tsshape.parquet` 에 캐시합니다.
- **이웃 확장 `NB_E_/NB_D_/NB_O_` (50, 참조 정답 사용)**: E — 과거·미래 참조 웨이퍼 편차(레짐 평균 대비)의 지수 가중 이동평균(반감기 0.5·2·8 시간, 2·5·15 장)과 그 차(국소 기울기), 같은 레짐과 같은 그룹의 다른 스테이지; D — 시간상 직전·직후 참조 웨이퍼 대비 이 웨이퍼의 상태 변화량(가공 시간, P·V 적분, 슬러리, 에어백 압력, 드레서·패드 사용량); O — 같은 웨이퍼 다른 스테이지의 편차와 시간 간격. **누수 방지**: 참조 행을 leave-one-out 만으로 처리하면 넓은 창에서 이웃 집합이 거의 같아 평균이 자기 정답의 단조 함수가 되고 트리가 그 순서를 외웁니다(탐색에서 CV 7.72 → 8.58 로 악화). 그래서 참조 행은 inner 5-fold 로 나눠 자기 폴드 밖 참조 행만으로 계산하고, 교차검증에서는 학습 폴드 안에서만 찾습니다.

### 2. 멤버 (`cmp_models.py`)

- **LightGBM** (레짐별): 580 컬럼 중 학습 행만으로 짧은 LightGBM 을 돌려 gain 상위 150 컬럼을 고른 뒤 본 모델을 학습합니다(폴드·레짐 안에서 고르므로 정직). 4 CPU 를 나눠 쓰는 환경에서는 레짐당 수백 행이라 `n_jobs=1` 이 가장 빠릅니다.
- **시퀀스 CNN + 표 특징 융합 신경망** (전역, PyTorch CPU): 단계별 13 채널 궤적을 64 점으로 보간하고 경과 시간 채널을 더한 [3, 14, 64] 텐서를 단계 공유 1D CNN 으로 인코딩(평균 + 최대 풀링, 없는 단계는 마스크)해 레짐 임베딩·compact 표 특징(분위수→정규 변환) MLP 가지와 이어붙입니다. 목표는 레짐별 학습 평균을 뺀 값(레짐 간 차이가 아니라 레짐 안 변동을 학습), Huber 손실, AdamW. 에폭 수는 학습 행의 20% 내부 분할로만 고른 뒤 전체 학습 행으로 다시 학습, 시드 3개 평균. 대회 후 연구(Appl. Sci. 2022) 의 deep + shallow 융합 아이디어입니다.
- **가우시안 프로세스** (레짐별): 입력 = 시각(시간 단위) + 드레서·패드·멤브레인 사용량, 커널 = 시간 RBF + 상태 RBF-ARD + White. 학습된 시간 길이척도 3~8 시간 — "최근 몇 시간의 수준 + 소모품 상태" 를 매끄럽게 보간하는 멤버로, 챔버 그룹 1 에서는 가중치 0.83 으로 주 멤버입니다.
- 이전 버전의 lgb_small·ExtraTrees·릿지는 세 멤버 위에서 nested CV 이득이 0.05 미만이라 뺐습니다.

### 3. 결합 (`cmp_blend.py`)

멤버별 5-fold OOF 예측을 레짐별 학습 정답 [min, max] 로 자른 뒤 레짐마다 비음수 최소제곱(NNLS, 합 1) 가중치를 맞춥니다 (시드 0: 1A lgb 0.03 / 신경망 0.14 / GP 0.83, 4A 0.45 / 0.46 / 0.09, 4B 0.71 / 0.21 / 0.08). 보고하는 CV 는 nested 값: 폴드마다 학습 폴드 OOF 로 클리핑 범위·가중치를 정해 held-out 폴드를 채점합니다. 멤버 선택도 nested CV 로만 했습니다(lgb 에서 시작해 이득이 0.05 이상인 멤버를 하나씩 추가: 7.013 → +신경망 6.714 → +GP 6.608 → 다음 후보 이득 0.039 로 중단; 시드 2 로 확인).

### 4. 도움이 되지 않은 것 (모두 CV 기준, 테스트·검증은 보지 않음)

- **XGBoost**: 기준 멤버 위에서 이득 없음. **CatBoost** 3종, **전역 huber LightGBM**, **Optuna 재조정 LightGBM**, **분위수 변환 MLP**: 탐색에서는 in-sample CV 가 좋아졌지만 테스트·검증으로 옮겨가지 않았고, 최종 층에서 nested CV 이득이 0.05 미만이라 뺐습니다(가장 나은 후보 lgb_xt 0.039).
- **잔차 목표** (이웃 평균 등을 뺀 값을 학습): CV 7.596 → 8.223 으로 크게 나빠짐. 트리가 offset 의 잡음을 되돌리려면 선형 보정을 배워야 하는데 어렵습니다.
- **레시피 지문** (단계별 궤적 k-means 군집·중심 거리·PCA): CV +0.074 로 나빠져 시퀀스 모양 특징에서 뺐습니다.
- **물리 기반 정적 특징 187개** (Preston 항 분해 등): 단독으로는 좋았지만 시퀀스 모양 특징과 같은 "단계 0 실제 연마 시간" 신호를 담아 그 위에서는 nested 이득 0.034 로 문턱 미달.
- **칼만 평활 특징**, **시간 커널·국소 직선·드레서 수명 이웃 가족**: 기존 이웃 특징과 겹쳐 잡음 수준(0.06 이하)이거나 나빠짐. **KNN 멤버**: 가중치 0.
- **결합 방식 대안** (절편, 릿지·LightGBM 메타 모델, 시간 평활, 수축): 클리핑 + 레짐별 NNLS 보다 나빴습니다.
- 학습 데이터의 연마량 수천 단위 값 4개는 측정 오류로 보고 뺐습니다(테스트·검증 최댓값 164).

탐색 기록과 각 실험의 수치는 `cmp2016/exp/` 에 있습니다 (`*.py` 는 실험 스크립트, `*.json` 은 결과). 실제 파이프라인은 `exp/` 를 import 하지 않습니다.

## 실행

원래 대회 링크는 사라져서 웹 아카이브에서 받습니다.

```bash
mkdir -p data/cmp2016/raw && cd data/cmp2016/raw
A=https://web.archive.org/web
F=https://www.phmsociety.org/sites/phmsociety.org/files
curl -L -C - -o train_test.zip "$A/20210224223550id_/$F/2016%20PHM%20DATA%20CHALLENGE%20CMP%20DATA%20SET.zip"
curl -L -C - -o validation.zip "$A/20210224234703id_/$F/2016%20PHM%20DATA%20CHALLENGE%20CMP%20VALIDATION%20DATA%20SET.zip"
curl -L -C - -o answers.zip "$A/20210224234745id_/$F/PHM16TestValidationAnswers.zip"
for z in train_test validation answers; do unzip -oq $z.zip -d $z; done
cd ../../..

pip install -r requirements.txt     # torch(CPU), lightgbm, scikit-learn, threadpoolctl 등
python cmp2016/run_cmp.py              # 약 7분 (4 CPU 공유, 특징 캐시 있을 때 405초), cmp2016/results.json
python cmp2016/build_cmp_dashboard.py  # cmp2016/dashboard/index.html
python -m pytest tests/test_cmp.py -q  # 특징 누수·자기 제외·형태 테스트
python cmp2016/fab_run.py --stage main  # 실시간(FAB) 시뮬레이션 시나리오 22개, 약 7분 (FAB.md)
```

- 첫 실행은 원본 센서 행에서 시퀀스 모양 특징과 시퀀스 텐서를 만들어 `data/cmp2016/` 에 캐시하므로 약 2분 더 걸립니다.
- 스레드: `OMP_WAIT_POLICY=PASSIVE`, LightGBM 1, torch 2, BLAS 2 (공유 CPU 4개 기준; `cmp_models.py` 에서 설정). 결과는 결정적입니다(같은 스레드 수에서 같은 수치).
- `--seed N` 으로 교차검증 폴드 시드를 바꿔 확인할 수 있습니다 (보고 수치는 시드 0).
